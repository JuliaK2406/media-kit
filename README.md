# Media kit: speaker.juliakrylova.com

Одна страница спикера плюс два PDF на скачивание: полный медиакит и one-sheet.
Весь текст живёт в одном файле, `content/site.yaml`. Страница и оба PDF собираются
из него автоматически, поэтому текст правится в одном месте и нигде не расходится.

Адрес превью: https://juliak2406.github.io/media-kit/
Боевой адрес после запуска: https://speaker.juliakrylova.com

## Как поменять текст (для Юлии)

1. Открой файл [content/site.yaml](content/site.yaml) прямо здесь, на GitHub.
2. Нажми иконку карандаша справа сверху (Edit this file).
3. Поменяй текст после двоеточия. Названия полей слева от двоеточия не трогай.
4. Нажми зелёную кнопку Commit changes, и ещё раз Commit changes в открывшемся окне.

Правила, чтобы ничего не сломалось:

- Меняй только текст после двоеточия. Названия полей и отступы в начале строк
  менять нельзя, отступы делаются пробелами, не табами.
- Если в твоём тексте есть двоеточие, кавычки или решётка, возьми весь текст
  в двойные кавычки: `"Пример: мой текст"`.
- Слово `TODO` в поле означает, что текст ещё не написан. На странице такое поле
  видно как жёлтая плашка. Замени `TODO` на настоящий текст, и плашка исчезнет.

## Что происходит после сохранения

GitHub сам пересобирает страницу и оба PDF. Это занимает три-четыре минуты.
Ход сборки виден на вкладке Actions: жёлтый кружок значит "собирается",
зелёная галочка значит "готово", красный крест значит "ошибка, напиши Стасу".
Когда появилась галочка, обнови страницу превью в браузере.

## Фотографии

Исходники лежат в папке [content/photos](content/photos). Добавить фото: открой
папку, нажми Add file, потом Upload files, перетащи файл, нажми Commit changes.

Загружай оригиналы в полном разрешении. Сайт сам сделает лёгкие версии для
страницы и версию для скачивания в пресс-ките. Оригиналы напрямую никогда
не отдаются.

Имя файла должно совпадать с тем, что указано в `site.yaml` (например, поле
`photo: julia-krylova.jpg`). Пробелы и заглавные буквы не страшны: файл
`Julia Krylova.jpg` тоже будет найден.

## Как добавить отзыв

Найди в `site.yaml` блок `testimonials:` и добавь ещё один кусок по образцу,
с теми же отступами:

```yaml
testimonials:
  - quote: "Текст отзыва"
    name: "Имя Фамилия"
    role: "Должность"
    company: "Компания"
  - quote: "Второй отзыв"
    name: "Имя"
    role: "Должность"
    company: "Компания"
```

## Как добавить тему выступления

Тот же принцип в блоке `topics:`:

```yaml
topics:
  - title: "Название темы"
    summary: "Два-три предложения о чём это."
    takeaways: ["Первый вывод", "Второй вывод", "Третий вывод"]
    formats: ["Keynote 45 min", "Workshop 2 h"]
```

## Запуск и защита от недописанного

Пока в `site.yaml` стоит `published: false`, страница закрыта от поисковиков,
а все поля с `TODO` видны как жёлтые плашки: сразу понятно, чего не хватает.

В день запуска Стас ставит `published: true`. Если при этом где-то остался
`TODO`, сборка нарочно падает: страница с недописанным текстом в интернет
не уедет.

## Что через site.yaml поменять нельзя

Структуру блоков, порядок секций, дизайн и вёрстку. Это делает Стас в коде.

## Для Стаса: настройка и локальная сборка

Разово в репозитории:

1. Settings, Pages, Build and deployment, Source: выбрать GitHub Actions.
   Workflow пытается включить это сам, но если первый запуск упал на шаге
   Setup Pages, включи вручную и перезапусти workflow (Re-run all jobs).
2. Перед запуском: в DNS домена juliakrylova.com добавить запись
   `CNAME, host: speaker, value: juliak2406.github.io`. Потом Settings, Pages,
   Custom domain: `speaker.juliakrylova.com`, дождаться проверки и включить
   Enforce HTTPS.
3. В день запуска: `published: true` в `content/site.yaml`. Перед этим
   `npm run check` должен показать ноль TODO.

Локальная сборка:

```
npm ci
npx playwright install chromium
npm run build        # страница, картинки и оба PDF в dist/
npm run check        # список незаполненных TODO
```

Нужен Node 20 или новее. В `dist/` ничего не редактировать, папка полностью
перезаписывается при каждой сборке и в git не попадает.
